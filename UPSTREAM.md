# Fixes to send upstream

Every fix this port carries that other people would benefit from, where it lives, and where it should go.
When one is merged upstream, drop our copy (fork commit or local manifest) and tick it here.

## LineageOS policy (Changelog 32, 2026-10-11)

- *"even though some devices using Linux Kernel versions 4.4 and 4.9 have been ported to LineageOS 23.2 and 24.0, we have
  decided to only accept LineageOS 22.2 submissions for these devices"*, because of their *"rather hacky"* platform commits.
  gts4lv is a 4.9 device, so **official 23.2/24 builds are closed to it**; official work for this tablet means `lineage-22.2`.
- 23.2/24 kernels must have *"1:1 eBPF backports, build fully without GCC, and many other important backported features"*.
  Ours: 2,469 commits on the LineageOS 22.2 kernel, ~2,445 upstream cherry-picks with provenance (`-x`; 529 `UPSTREAM:`,
  1,611 `BACKPORT:` from ExyHyperBrick), ~23 own glue commits (P3/P4 build fixes, ld_abs fix, EROFS defconfig + compat).
  Compiled entirely by clang/LLD (no GCC in any `.comment`, no GCC tool in any kernel `.cmd`), but the arm64 Makefile still
  insists on a `CROSS_COMPILE_ARM32` prefix for the compat vDSO, hence `local_manifests/24/gcc-arm32.xml`.
- Exceptions: Charter changes need 3 Project Directors ([charter](https://github.com/LineageOS/charter/blob/main/device-support-requirements.md#attaining-exceptions)).
  The 4.9 rule is a project decision, not a Charter section, and this port carries exactly the platform reverts it names
  (#6, #7) plus `ro.bpf.kver_override` and an LTE radio HAL below FCM 7: an exception is unlikely.
- Shims are now commonized in [`android_hardware_lineage_compat`](https://github.com/LineageOS/android_hardware_lineage_compat):
  our device-tree `shims/libwfdservice` (the 3-argument `setDeviceConnectionState` bridge) belongs there, next to #8.
