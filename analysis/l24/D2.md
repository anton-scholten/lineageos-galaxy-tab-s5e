# D2: let the thermal HAL read the `sec-*-thermistor` nodes

Device-tree fix, branch `port/l24-dt-6` @ `a8b5d8e`, cut from the device fork's `lineage-24.0`
(`c2fe044`). One commit, three files, +3 lines. No deletions.

The cross-cutting investigation packet — symptom, measurements, both fixes and the
decisions needed — is [charging-notification.md](charging-notification.md), which lives on
branch `agent/D1`.

Found during an owner-directed debugging session on 2026-10-12 on a tablet running the **23.2**
release build. Independent of D1 — the two branches are both cut from `lineage-24.0` and neither
contains the other, so **both must be merged**.

## 1. Finding

Three SELinux denials, live and enforcing (`permissive=0`):

```
avc: denied { getattr } for path="/sys/devices/virtual/sec/sec-ap-thermistor/temperature"
  scontext=u:r:hal_thermal_default:s0  tcontext=u:object_r:sysfs:s0  tclass=file  permissive=0
avc: denied { getattr } for path="/sys/devices/virtual/sec/sec-pa-thermistor/temperature"
  scontext=u:r:hal_thermal_default:s0  tcontext=u:object_r:sysfs:s0  tclass=file  permissive=0
avc: denied { getattr } for path="/sys/devices/virtual/sec/sec-bk-thermistor/temperature"
  scontext=u:r:hal_thermal_default:s0  tcontext=u:object_r:sysfs:s0  tclass=file  permissive=0
```

All three resolve to the **generic `sysfs` type** — nothing labels them.

This is the same class of gap that `1188e2b` closed one commit earlier: that commit granted
`hal_thermal_default` access to `sysfs_batteryinfo` and `sysfs_switch` and added wakeup-node
labeling, but did not cover the thermistor nodes. The port's sepolicy work has been fixing these
one at a time; this is the next one.

## 2. The fix

Follows the pattern already established in this tree (`e7652fc`, `efd222f`, `1188e2b`):

| file | change |
|---|---|
| `sepolicy/vendor/file.te:53` | `type sysfs_sec_thermistor, fs_type, sysfs_type;` — alongside the existing `sysfs_sec_keypad` / `sysfs_sec_switch` pair (`file.te:51-52`) |
| `sepolicy/vendor/file_contexts:193` | labels the three directories, placed with the other `/sys/devices/virtual/sec/` rules |
| `sepolicy/vendor/hal_thermal_default.te:2` | `r_dir_file(hal_thermal_default, sysfs_sec_thermistor)` |

`r_dir_file` matches the two existing lines in that file.

## 3. Checks done before committing

- **No shadowing rule.** `file_contexts` has no broad `/sys/devices/virtual/sec(/.*)?` and no
  `/sys/devices/platform(/.*)?` rule, so the new entry cannot be beaten by a shorter stem. The
  ordering hazard called out in `1188e2b` ("fc_sort ranks by stem length") does not apply here.
- **No duplicate type.** `grep -rn "type sysfs_sec_thermistor"` over `system/sepolicy`,
  `device/sepolicy` and the vendor trees returns nothing, so the declaration is safe.
- **Style match.** The new `file_contexts` line omits the `--` meta column, matching its
  `sec_keypad` / `sec_switch` / `sec_tsp` siblings rather than the `mdnie` line.

## 4. Confidence

**High** for correctness of the sepolicy change itself. It is additive, mirrors a pattern already
reviewed and merged twice in this tree, and is narrowly scoped to three known paths.

**Not verified:** that these three nodes are the *only* remaining thermal HAL denials. Other
denials may exist that were not captured in this session, and the port's sepolicy has a history of
one-at-a-time discovery.

## 5. Not verified / risks for the reviewer

1. **No build was run.** Per the owner's instruction, committed but unbuilt.
2. **Not build-verified against a sepolicy compile.** A syntax or macro error would only surface in
   a build. The change reuses only `r_dir_file` and an existing attribute/type set, so the risk is
   low but nonzero.
3. **No `genfscon` fallback.** Only `file_contexts` is used. That is deliberate and matches
   `1188e2b`, whose commit message records that `ueventd restorecon` re-labels sysfs paths on every
   uevent and clobbered the `genfscon` labels set by `e7652fc`. These nodes are static, but the same
   restorecon pass applies, so `file_contexts` is the reliable location.
