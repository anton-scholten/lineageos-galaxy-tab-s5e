## 6. What L7 should expect

In rough likelihood order:

1. **`libui` link failure** without commit 4 — `-DLEGACY_GRALLOC` is the only thing that keeps the gralloc2/3/4
   paths out of `libs/ui` (`frameworks/native/libs/ui/Android.bp:136-139` @ `lineage-24.0`). Near-certain that
   the flag is required; the exact failure text is not known.
2. **ION symbol errors** if legacy libion is not sufficient for every blob that referenced ION.
   `TARGET_USES_ION` is still set, so 24.0 should keep the legacy path.
3. **`disable_configstore` was mandatory** — had it stayed, the build would fail on an undefined module.
4. **Watch, do not pre-fix:** `vendor.qti.hardware.capabilityconfigstore`, `ro.bpf.kver_override` being read
   (netbpfload gates at `NetBpfLoad.cpp:1578` and `:1584` are now fatal `return 7`), the new
   `/apex/com.android.resolv` rejection at `:1542`, and `/metadata/aconfig` SELinux labelling (unchecked by L3;
   our `b26a9d6` depends on that path, and 24.0 also creates it at early-init).

Anything in category 3 or 4 that fails is an escalation, not a fix: no `BUILD_BROKEN_*`, no permissive policy,
no deleted code.

## Problems

1. **Local branch confusion, harmless but worth knowing.** After committing, the working clone's `HEAD` was on
   `lineage-24.0` with the four commits applied, because `--single-branch` checked that out. Creating and
   pushing `port/l24-dt-1` from it was correct, but the local `lineage-24.0` briefly pointed at `5af53f1` instead
   of `1188e2b`. Resolved by resetting it. **Verified the remote `lineage-24.0` never moved** (see §5) — a second
   `ls-remote` confirms `1188e2b14a5a`.
2. Pushing the new branch failed once with `src refspec port/l24-dt-1 does not match any`, because the branch
   existed only as a remote ref at that point. Fixed with `git branch port/l24-dt-1` first.
3. **`git push <remote> <sha>:refs/heads/x` from a fresh clone fails** with `remote: fatal: early EOF`. An
   empty clone has no objects to pack. Push from an existing checkout instead (same lesson as L5).
