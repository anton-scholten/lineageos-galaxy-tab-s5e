## Proposed resolution
DROP the kernel/sched/ems/energy.c half: keep sdm670's state, i.e. **the file must stay absent**.
Do not accept git's suggestion to leave "Version 3d3946a898f4 of kernel/sched/ems/energy.c" in the
tree - that would add an orphan Exynos-only file that nothing compiles (sdm670 has no Makefile rule for
it, no `ems.h`, and none of the 15 sibling EMS files it depends on), and it would sit in the tree as
dead, misleading code. Accept the kernel/sched/fair.c hunk as merged - it is already in place and it is
where the feature actually lives on a Qualcomm device.
## Confidence
high: the file's absence from sdm670 is provable three independent ways (`ls-tree` of the directory,
`ls-tree` of the file, and a tree-wide grep for sched/ems references), and the fairness of dropping it
does not depend on guessing because dropping loses nothing that sdm670 ever had - it is the Exynos
scheduler, which a Qualcomm SDM670 board cannot use. The only assumption is that nobody intends to port
the whole Samsung EMS scheduler to sdm670, which nothing in this project suggests.
