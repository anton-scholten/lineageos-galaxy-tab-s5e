## Proposed resolution
DROP — and note the commit cannot compile as it stands, so a plain MERGE would break the build.

`config->link_status_property` is *used* by the commit but the field is **never declared**, in either tree:
- sdm670: `struct drm_mode_config {` lives in `include/drm/drm_crtc.h` (there is no
  `include/drm/drm_mode_config.h` in this tree) and its property fields run
  `edid_property` … `suggested_y_property` with no `link_status_property`
  (`include/drm/drm_crtc.h:1119-1343 @ a30605a54f3b`; the struct closes right after `suggested_y_property`).
- Series head `baa585f67e0e`: identical — `git grep -n 'link_status_property' baa585f67e0e` finds only the
  *uses* (`drivers/gpu/drm/drm_atomic.c:1035,1085`, `drivers/gpu/drm/drm_connector.c:248,656`) and
  `include/drm/drm_connector.h:794` (the setter prototype), never a declaration. So the ExyHyperBrick tree
  itself does not compile this patch; the trial replay inherited the breakage.
- The missing prerequisite is upstream patch 1/5 of Manasi Navare's "Handle Link Training Failure during
  modeset" series, `drm: Add a new connector property for link status`
  (<https://lists.freedesktop.org/archives/dri-devel/2016-November/date.html>), which is what adds the
  `struct drm_mode_config` field. It is **not** in the series
  (`git log --oneline d54533f1546b..baa585f67e0e --grep='link_status' -i` → only this commit), and its SHA is
  not present in this clone (`git log --all -S'link_status_property' -- include/drm/drm_crtc.h` → empty).

Why DROP rather than MERGE is the safe call here: the feature is opt-in per its own commit message and is
only used by DisplayPort drivers (i915/amdgpu/msm-dp); sdm670 has no DP link to retrain, nothing else in the
series references `link_status` (`git grep -l link_status baa585f67e0e` shows only the files this commit
touches), and keeping it would require hand-adding the `link_status_property` field to `struct drm_mode_config`.
That is a code change, not a conflict resolution, so it belongs in a deliberate follow-up patch, not here.

Also flagged in the commit message itself, by krazey:
`Conflicts: drivers/gpu/drm/drm_atomic.c / drivers/gpu/drm/drm_connector.c / include/drm/drm_mode_config.h`
— his note names `drm_mode_config.h`, the same file that is missing the field, which corroborates the
prerequisite analysis.

If the lead decides to keep the feature anyway, the resolution order is: (1) merge the one conflict block by
keeping both sides (all 25 of ours plus the 3 new lines), then (2) hand-add
`struct drm_property *link_status_property;` to `struct drm_mode_config` in `include/drm/drm_crtc.h`
next to `path_property`. Step 2 is a manual addition, not something `git` can resolve.
