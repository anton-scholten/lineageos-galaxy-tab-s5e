## Proposed resolution
MERGE: for Block 1 keep **both** `select` lines - `arch/powerpc` is irrelevant to this device, so this is about
Kconfig staying valid:
```kconfig
	select ARCH_HAS_ELF_RANDOMIZE
	select ARCH_HAS_FORTIFY_SOURCE
	select ARCH_HAS_NON_OVERLAPPING_ADDRESS_SPACE
	select OF
```
Do **not** resolve Block 1 by taking ours: that would leave `select ARCH_HAS_NON_OVERLAPPING_ADDRESS_SPACE`
missing on powerpc, which contradicts upstream. Taking theirs would silently drop
`ARCH_HAS_FORTIFY_SOURCE` on powerpc, so merge both lines instead.
Take the rest of the commit as-is (`init/Kconfig`, `arch/arm`, `arch/arm64`, `arch/x86`, `arch/mips`).
**Important for the port:** because `arch/arm64/Kconfig` gains
`select ARCH_HAS_NON_OVERLAPPING_ADDRESS_SPACE`, `CONFIG_ARCH_HAS_NON_OVERLAPPING_ADDRESS_SPACE` will be `y`
on the Tab S5e, so the legacy `bpf_probe_read()` / `bpf_probe_read_str()` helpers stay exposed - which is what
Android's `bpfloader`/`netbpfload` rely on. Verify this after the defconfig work (task K6).
If the lead hits Block 2 (means an earlier BPF-trace commit was skipped): sdm670's
`kernel/trace/bpf_trace.c:477-480` predates the user/kernel helper split, so the move has no clean target.
Either drop Block 2 entirely (behaviour on arm64 is identical once the symbol is `y`) or take theirs' block
verbatim - but do not take ours, which deletes nothing and keeps the working legacy cases.
