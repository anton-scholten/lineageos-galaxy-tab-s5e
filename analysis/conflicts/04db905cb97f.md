## Why it conflicts
merge-tree on its own: conflicts. Isolated result tree: `d068de7fcb68e9e7eb89066d7cbcf983565b9565`.

- Block 1, fs/fuse/dev.c ~line 1963, in `fuse_dev_do_write()`, immediately after
  `fuse_copy_finish(cs);` and before `spin_lock(&fpq->lock);`: ours = sdm670's single line
  `fuse_setup_passthrough(fc, req);`; theirs = the new `#ifdef CONFIG_FUSE_BPF ... #endif` block that
  resolves `FUSE_LOOKUP` / `FUSE_LOOKUP|FUSE_POSTFILTER` replies and does
  `fget(out->backing_fd)` / `fget(out->bpf_fd)` into `entry->backing_file` / `entry->bpf_file`.
  Purely adjacent: two different statements at the same insertion point.

Root cause: exactly the same as 021499e96a40 - sdm670 carries Samsung's FUSE passthrough feature, which
inserted `fuse_setup_passthrough(fc, req);` into the same spot in the same function.
`sdm670`'s `fuse_setup_passthrough()` lives in fs/fuse/passthrough.c with its header
fs/fuse/fuse_passthrough.h (1 hit each in a30605a54f3b).

## Proposed resolution
MERGE for the single hunk; PREREQ for the symbols.
- Prerequisite: `435bb390114e` BACKPORT: ANDROID: fuse-bpf: Add request UAPI (batch K3-1, itself a
  conflict on include/uapi/linux/Kbuild) supplies `struct fuse_entry_bpf`,
  `struct fuse_entry_bpf_out`, `FUSE_ACTION_REPLACE` and `FUSE_POSTFILTER` in
  include/uapi/linux/android_fuse.h. Also needed: `90d81d6b357b` BACKPORT: ANDROID: fuse-bpf: Add lookup
  backing helpers (CLEAN in the trial; creates fs/fuse/backing.c and the `fuse_lookup_io` /
  `fuse_entry_bpf` plumbing in fs/fuse/fuse_i.h) and `462a37becb45` BACKPORT: ANDROID: fuse-bpf: Add
  request dispatcher (batch K3-2, conflict).
- Hunk, fs/fuse/dev.c ~1963: keep **both**, Samsung first then the new block:
  `fuse_setup_passthrough(fc, req);` then the whole `#ifdef CONFIG_FUSE_BPF ... #endif` region, then
  `spin_lock(&fpq->lock);`. Order does not matter - `fuse_setup_passthrough()` only touches
  `req->passthrough_filp`, while the new block only reads `req->in.h.opcode` / `req->out.args[1]` and
  takes `fget()` references - but taking "theirs" wholesale and dropping
  `fuse_setup_passthrough(fc, req);` silently disables FUSE passthrough read/write on this tablet
  (fs/fuse/file.c:970 and :1244 depend on `ff->passthrough_filp`). That is a functional regression that
  would not show up as a build error.
- The whole block is inside `#ifdef CONFIG_FUSE_BPF`, so it costs nothing if the lead ends up not
  enabling that config. Keep the `#ifdef`/`#endif` - do not "simplify" it away.
