## Proposed resolution
MERGE, per block:
- **Block 1: keep ours, do NOT paste theirs.** Accepting theirs' inserted copy would define
  `__hrtimer_hres_active`, `hrtimer_hres_active` and `hrtimer_force_reprogram` a **second** time (duplicate symbols,
  and an "unused function"/redefinition build break). Instead apply the commit's real content change to sdm670's
  existing copy at `kernel/time/hrtimer.c:565-566` and `:589` @ a30605a54f3b:
  1. delete `if (!cpu_base->hres_active)` + its `return;` (lines 565-566);
  2. at line 589 change `if (cpu_base->hang_detected)` to `if (!cpu_base->hres_active || cpu_base->hang_detected)`;
  3. insert the comment "If hres is not active, hardware does not have to be reprogrammed yet." above that block.
  Using `cpu_base->hres_active` (not `__hrtimer_hres_active(cpu_base)`) is fine here: sdm670's
  `__hrtimer_hres_active()` is a one-line wrapper returning `cpu_base->hres_active`
  (`kernel/time/hrtimer.c:545-548` @ a30605a54f3b) and the code is inside the ifdef where the bit exists.
- **Block 2: keep ours, drop only the `#endif`.** The `#ifdef CONFIG_HIGH_RES_TIMERS` at
  `kernel/time/hrtimer.c:881` @ a30605a54f3b and its `#endif` at `:892` are both deleted; the Samsung
  `out:` label + PINNED-preserving `WRITE_ONCE` at `:894-901` must be **kept verbatim**. It is load-bearing:
  `remove_hrtimer()` clears `HRTIMER_STATE_PINNED` right after (`kernel/time/hrtimer.c:930` @ a30605a54f3b) and
  `HRTIMER_STATE_PINNED`/`HRTIMER_PINNED_SHIFT` exist only in sdm670 (`include/linux/hrtimer.h:58,63` @ a30605a54f3b).
- Removing the `#ifdef` is safe even if sdm670's `hrtimer_force_reprogram()` stays inside it, because the
  `#else` branch provides an empty stub (`kernel/time/hrtimer.c:728-729` @ a30605a54f3b).
