## Proposed resolution
MERGE: (1) include/uapi/linux/android/binder.h - keep **all** defines: `struct binder_freeze_info`,
`struct binder_frozen_status_info`, `BINDER_FREEZE _IOW('b', 14, struct binder_freeze_info)`,
`BINDER_GET_FROZEN_INFO _IOWR('b', 15, struct binder_frozen_status_info)`, plus the existing
`BINDER_SET_SYSTEM_SERVER_PID`/`BINDER_ENABLE_ONEWAY_SPAM_DETECTION` arms from `8f50d9eb049e`.
Optionally renumber the two 4.9-era leftovers to 16/17 to match the upstream ABI and kill the
duplicate, but see Problems before doing that.
(2) drivers/android/binder.c - keep **both** sides' `case` arms in `binder_ioctl()`: ours'
SET_SYSTEM_SERVER_PID / ENABLE_ONEWAY_SPAM_DETECTION and theirs' BINDER_FREEZE. The `binder_freeze_info`
arm depends on `struct binder_proc` fields this same commit adds (`is_frozen`, `outstanding_txns`,
`freeze_wait`), which all merged cleanly, so it can go in as-is.
confidence note: the merge itself is high-confidence; the optional renumbering is a judgement call and
is listed under Problems rather than recommended.

## Problems
1. **Do not renumber blindly.** `BINDER_SET_SYSTEM_SERVER_PID` at nr 14 is what the whole Exynos 4.9
   line (and sdm670's own future port) uses; Android's userspace constant comes from the kernel uapi
   header, so the two sides must agree. If the lead renumbers it to 16 (as upstream
   android-5.10+ does) then `BINDER_ENABLE_ONEWAY_SPAM_DETECTION` must move too, and the
   `drivers/android/binder.c` `switch` must be checked against whatever userspace expects. I could
   not verify the Android 16 numbering from here: the trees available on this machine
   (`LineageOS/android_system_core` at ~/work/clone-R7/core) do not contain libbinder, which
   lives in `frameworks/native`. Suggested check for the lead: `git grep BINDER_FREEZE` in a clone of
   `LineageOS/frameworks/native` branch lineage-23.2.
2. The batch label `optional` is wrong for this commit and for `e5dba8a19d08` (next brief). The
   heuristic in `analysis/exyhyperbrick-trial/classify.py:15` has no `binder` keyword, so both binder
   ioctl commits landed in the `optional` group. Binder freeze is an Android 12+ feature; if Android 16
   init/ActivityManager uses the freezer path, dropping these two commits breaks app state management,
   not just a nice-to-have. Treat both as effectively required.
