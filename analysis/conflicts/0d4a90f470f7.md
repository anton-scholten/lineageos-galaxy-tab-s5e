## Why it conflicts
merge-tree on its own: conflicts (1 block, 1 file) - tree `63e1239a84dd4dda7fe730869fb4986539fb9b6d`
- Block 1, kernel/time/hrtimer.c ~line 1170, inside `hrtimer_active()`:
  ours (sdm670) = `if (((timer->state & ~HRTIMER_STATE_PINNED) != HRTIMER_STATE_INACTIVE) || cpu_base->running == timer)`
  theirs (series) = `if (timer->state != HRTIMER_STATE_INACTIVE || base->running == timer)`.

  `____cacheline_aligned` is available in sdm670 (`a30605a54f3b:include/linux/cache.h:34`) and was already
  used by this very header before the change (`a30605a54f3b:include/linux/hrtimer.h:199`), so no build break.
## Already in sdm670?
partly. Evidence: sdm670 has the *old* layout - `seqcount_t seq` / `struct hrtimer *running` still live in
`struct hrtimer_cpu_base` (`a30605a54f3b:include/linux/hrtimer.h`), and `hrtimer_callback_running()` at
`a30605a54f3b:include/linux/hrtimer.h:442` still reads `timer->base->cpu_base->running`. So the change this
commit makes has **not** been applied. Every `cpu_base->running` / `cpu_base->seq` reference in sdm670 is
inside the two files this commit touches (`git grep -n 'cpu_base->running\|cpu_base->seq' a30605a54f3b --
kernel/ include/ drivers/` returns hits only in `include/linux/hrtimer.h` and `kernel/time/hrtimer.c`), so
the move is self-contained.
Separately: the CAF `HRTIMER_STATE_PINNED` extension that sdm670 adds and that the conflict is about exists
only in sdm670 - `git grep -n HRTIMER_STATE_PINNED baa585f67e0e -- include/linux/hrtimer.h kernel/time/hrtimer.c`
returns **no hits**, and the series base `d54533f1546b` has none either. So Exy deleted this feature
outright; taking theirs blindly would silently drop sdm670's pinned-timer support.
## Proposed resolution
MERGE: keep sdm670's pinned-timer test, take the commit's variable rename. Resolve the block to
```c
		if (((timer->state & ~HRTIMER_STATE_PINNED) !=
		      HRTIMER_STATE_INACTIVE) || base->running == timer)
```
i.e. one word changes against ours: `cpu_base->running` -> `base->running`. Take the rest of the commit as-is.
Post-merge check for the lead: all five other `HRTIMER_STATE_PINNED` uses must survive
(sdm670 `kernel/time/hrtimer.c:901,930,983,1659` and `include/linux/hrtimer.h:77`; in the merge-tree result
they are at `:899,928,981,1662`). If any later series commit in the `kernel/time` group rewrites one of those
lines, keep the `HRTIMER_STATE_PINNED` masking there too.
