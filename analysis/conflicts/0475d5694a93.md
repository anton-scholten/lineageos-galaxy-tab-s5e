## Proposed resolution
MERGE: resolve the one block to sdm670's existing list plus the single declaration this commit really adds:
```c
struct fscrypt_info;
struct fscrypt_operations;
struct bpf_local_storage;
```
i.e. add `struct bpf_local_storage;` after `struct fscrypt_operations;` and do **not** add
`struct fsverity_info;` / `struct fsverity_operations;` (nothing in sdm670 defines or references them, and adding
forward declarations for types that do not exist is harmless but noise - dropping them keeps the tree honest).
Do **not** resolve by taking ours: dropping `struct bpf_local_storage;` breaks the merged
`struct bpf_local_storage __rcu *i_bpf_storage;` member at `include/linux/fs.h:658` and therefore the build.
Prerequisite note for the lead: this commit needs `6f11c86c92bb` and `f50d4f252709` (both CLEAN in the trial) plus
the rest of the earlier BPF series to have landed; if either was skipped the `include/linux/bpf_local_storage.h`
and `include/linux/bpf_types.h` modify/delete conflicts reappear and `bpf_inode_storage_free()` /
`inode_storage_map_ops` will be undefined.
