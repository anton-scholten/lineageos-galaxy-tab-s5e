## Proposed resolution
MERGE: for the single block, **keep the empty side** - delete CAF's comment and the duplicate
`if (!dst_vma->vm_userfaultfd_ctx.ctx) goto out_unlock;` from that position. The check itself is not lost: the
auto-merge has already placed the same test higher up, right after `if (!dst_vma) goto out_unlock;`, which is where
upstream 27d02568f529 wants it (it must run before the bounds check so that a VMA that vanished or was never
registered returns `-ENOENT` instead of `-EINVAL`). Upstream's "Be strict..." comment replaces CAF's wording; the
semantics CAF wanted - only allow `__mcopy_atomic` on uffd-registered ranges, i.e. enforce the `VM_MAYWRITE` check
done at registration time - are preserved.

Accept the rest of the commit as merged, including the removal of the uffd-ctx check from
`__mcopy_atomic_hugetlb()` - that removal is safe because `__mcopy_atomic()` now checks it before calling into the
hugetlb path, and that whole function is `#ifdef CONFIG_HUGETLB_PAGE` (off on gts4lv anyway).
