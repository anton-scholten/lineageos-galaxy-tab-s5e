## Proposed resolution
MERGE - three hand edits, everything else from the series as-is.
1. `include/uapi/linux/android/binder.h`: keep **only** the new
   `#define BINDER_ENABLE_ONEWAY_SPAM_DETECTION _IOW('b', 16, __u32)`. Drop `BINDER_SET_SYSTEM_SERVER_PID` (that is a
   Samsung ioctl 14 with no implementation on sdm670) and drop the duplicated `BINDER_GET_NODE_INFO_FOR_REF` (already
   present at line 276). Do not renumber: ioctl 16 is what AOSP libbinder expects, so this matches Android 16 userspace
   and also leaves 14/15 free.
2. `drivers/android/binder.c`: keep **only** `case BINDER_ENABLE_ONEWAY_SPAM_DETECTION:` (place it right before
   `default:` in `binder_ioctl()`). Drop `case BINDER_SET_SYSTEM_SERVER_PID:` - it would **not compile** on sdm670,
   because `system_server_pid` only exists in the Exynos tree (`drivers/android/binder.c:81` @ `8f50d9eb049e^`). The
   rest of that case-block compiles as-is: `binder_inner_proc_lock()`/`_unlock()` are defined at
   `drivers/android/binder.c:726` and `:741` @ `a30605a54f3b`, and `proc->oneway_spam_detection_enabled` is added by
   the same commit.
3. `drivers/android/binder_alloc.h`: keep sdm670's `unsigned clear_on_free:1;` (do **not** apply the commit's
   "this tree has no clear_on_free bit" assumption - it is true for the Exy tree, false for sdm670, where
   `clear_on_free` is read/written at `drivers/android/binder.c:3303`, `drivers/android/binder_alloc.c:695`, `:697`,
   `:794`, `:796`). So the bitfield must become `free:1, clear_on_free:1, allow_user_free:1, async_transaction:1,
   oneway_spam_suspect:1, debug_id:27` - i.e. narrow `debug_id` from 28 to **27**, not leave it at 28 as the merged tree
   currently does (the auto-merge produced `oneway_spam_suspect:1` + `debug_id:28` on top of sdm670's `clear_on_free`,
   which overflows the 32-bit word). Narrowing is safe: `buffer->debug_id` is only printed, never sized by anything
   (`drivers/android/binder_alloc.c:848` @ `a30605a54f3b`, the only use of that field).
