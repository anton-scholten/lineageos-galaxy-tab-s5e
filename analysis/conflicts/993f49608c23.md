## Summary
The big one, and the most under-reported conflict in the batch: it converts the whole sockmap
implementation to a new generic `sk_msg` layer (deletes `kernel/bpf/sockmap.c` (2091 lines), adds
`include/linux/skmsg.h`, `net/core/skmsg.c`, `net/core/sock_map.c`, `net/ipv4/tcp_bpf.c`). The TSVs call
it 1 file / 1 block; standalone it is 9 files / 12 blocks. It is blocked on `86d4a3ab7e8d`
"BACKPORT: bpf: Check attach type at prog load time" (series position 803), which introduces the
2-argument `bpf_verifier_ops.get_func_proto()` that sdm670 lacks; without it, `net/core/filter.c` block 1
(sdm670's 1-arg `cg_skb_func_proto` vs the series' 2-arg `lwt_inout_func_proto`) has no correct answer.
The per-block plan for after the prerequisites land is in the brief.
