  commit converts all of them — verified in the replay result, where they read `atomic_long_t` /

Dropping it is harmless if the lead prefers: it is a type-consistency cleanup, in the optional group, and on this
device nothing truncates or overflows in practice. sdm670's `lazy_max_pages()` is
`fls(num_online_cpus()) * CONFIG_VMAP_LAZY_PURGING_FACTOR * 1MB / PAGE_SIZE` (`mm/vmalloc.c:665-666`, factor
default 32 on arm64 — `mm/Kconfig:641-643` @ `a30605a54f3b`), so on a tablet it returns tens of thousands of pages
and `resched_threshold = 2 *` that — comfortably inside `int`, so `7c9b3c4119eb`'s `(int)` cast loses nothing
here. The only residue of dropping this commit is that
`atomic_read(&vmap_lazy_nr) < resched_threshold` compares `int` against `unsigned long`, which is a sign-compare
the kernel does not warn about by default. Keeping it is also harmless and is the upstream shape.
