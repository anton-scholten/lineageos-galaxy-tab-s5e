## Why it conflicts

`2f5f6ed8168eeb3e870122140902fa041ff62415`) reports exactly one content conflict. Not a stacked-replay artefact.

  `.procname = "swap_ratio"` (`.data = &sysctl_swap_ratio`, mode 0644) and `.procname = "swap_ratio_enable"`

  theirs (series) = `#ifdef CONFIG_USERFAULTFD` with one entry, `.procname = "unprivileged_userfaultfd"`,
  `.data = &sysctl_unprivileged_userfaultfd`, `.maxlen = sizeof(sysctl_unprivileged_userfaultfd)`, mode 0644,
  `.proc_handler = proc_dointvec_minmax`, `.extra1 = &zero`, `.extra2 = &one`. Both sides are pure insertions at the
  same anchor and both borrow the same shared closing `	},` + `#endif` tail, so git cannot place them.

Everything else in the commit applies cleanly: the `#include <linux/userfaultfd_k.h>` line in `kernel/sysctl.c`
(auto-merged), `int sysctl_unprivileged_userfaultfd __read_mostly = 1;` in `fs/userfaultfd.c`, the

`userfaultfd_file_create()`, and the `Documentation/sysctl/vm.txt` entry. Default is **1** (unprivileged userfaultfd
allowed), same as upstream, so nothing changes for Android unless the sysctl is set to 0.

## Proposed resolution
MERGE: keep sdm670's `#ifdef CONFIG_SWAP` group (both `swap_ratio` and `swap_ratio_enable`) **and** add the series'
`#ifdef CONFIG_USERFAULTFD` group immediately after it, before the terminating `	{ }` entry of `vm_table[]`. Do not
delete the swap_ratio entries to make room - they are a Samsung/CAF addition
(`sysctl_swap_ratio` / `sysctl_swap_ratio_enable` are defined in `mm/swap_ratio.c:31` and declared in
  `include/linux/swap.h:342` @ `a30605a54f3b`) and dropping them would change
swap behaviour. No other file needs a decision.
