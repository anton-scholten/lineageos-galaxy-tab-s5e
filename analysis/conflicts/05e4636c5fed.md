## Proposed resolution
MERGE, per block:
1. `include/uapi/asm-generic/socket.h` ~line 97: add **only**
   `#define SCM_TIMESTAMPING_PKTINFO	58` (+ blank line) after `#define SO_COOKIE 57`.
   **Do not import the `// KNOX NPA` block.** It is not part of this commit; pulling it in here would
   also drag in `#if ANDROID_VERSION < 90000`, which is the known build error tracked as **K4b**
   (`include/uapi/asm-generic/socket.h:112`, `analysis/build-test/port-first-errors.txt`). If the lead
   *wants* Knox NPA, it belongs to whichever series commit actually adds it, handled on its own.
2. `include/uapi/linux/net_tstamp.h` ~line 29: keep all three lines -
   `SOF_TIMESTAMPING_OPT_STATS = (1<<12),`, `SOF_TIMESTAMPING_OPT_PKTINFO = (1<<13),` and **one**
   `SOF_TIMESTAMPING_LAST = SOF_TIMESTAMPING_OPT_PKTINFO,`. Dropping `OPT_STATS` would lose the
   earlier `b39e74c6d46e` feature; `LAST` must be the highest bit, and `OPT_PKTINFO` (1<<13) is.
   Note the naive keep-both leaves two `SOF_TIMESTAMPING_LAST` lines in the blob
   (`8d0ff704a201:include/uapi/linux/net_tstamp.h:31` and `:36`) - delete ours.
3. `net/socket.c` ~line 683: add **only** `static void put_ts_pktinfo(struct msghdr *msg, struct sk_buff *skb)`.
   Do not import `kernel_sendmsg_locked()` or `skb_is_err_queue()` here; `skb_is_err_queue()` comes from
   `b39e74c6d46e` and `kernel_sendmsg_locked()` from an earlier commit - both are already in the tree by
   the time this commit is applied in series order.
4. `net/socket.c` ~line 770: take theirs - the braced `if (shhwtstamps && ... ) { empty = 0;
   if ((sk->sk_tsflags & SOF_TIMESTAMPING_OPT_PKTINFO) && !skb_is_err_queue(skb))
   put_ts_pktinfo(msg, skb); }` followed by `if (!empty) {`.
Accept the auto-merged `#include <linux/types.h>` and `struct scm_ts_pktinfo` as they are.
Net effect: no code is lost from either side in any of the four blocks.
