## Proposed resolution
MERGE: keep both sides of each block.
- scripts/link-vmlinux.sh block 1: keep sdm670's RTIC MP block **and** add theirs' BTF block, RTIC first then
  BTF. That order matters: the RTIC block appends `$RTIC_MP_O` to `KBUILD_VMLINUX_MAIN`, and `gen_btf()`
  internally calls `vmlinux_link "" .tmp_vmlinux.btf`, so with BTF first the temporary BTF image would be
  linked without the RTIC placeholder and the later RTIC size check
  (a30605a54f3b:scripts/link-vmlinux.sh:391-398, `cmp -s .tmp_rtic_mp_sz1 .tmp_rtic_mp_sz2`) could see a
  different object layout. Do not drop the RTIC block - it is a Qualcomm feature and sdm670's defconfig may
  enable RTIC_MPGEN.
- kernel/bpf/Makefile block 2: take theirs. In the stacked tree `reuseport_array.o` is already present from the
  CLEAN commit `57ab06cd8199`, so the effective change is the three-line `sysfs_btf.o` stanza.
**Build prerequisites the lead must not miss** (verified, both would break the build, not just the feature):
1. `${PAHOLE}` is referenced by `gen_btf()` but sdm670's top-level `Makefile` has no `PAHOLE` variable
   (`git grep -n PAHOLE a30605a54f3b -- Makefile scripts/` -> nothing). It is added by
   `8a953036e3b56412076ff6f67fa6c3b5720d3e6e` "BACKPORT: kbuild: Add vmlinux BTF generation option"
   (Makefile + lib/Kconfig.debug), which is a **CONFLICT** commit in another batch. If that one is dropped or
   resolved without the `PAHOLE = pahole` line and the `export ... PAHOLE ...` line, then
   `command -v ${PAHOLE}` fails, `gen_btf` returns 1, and this commit's `exit 1` kills every build.
2. `gen_btf()` requires pahole >= 1.13 and errors out otherwise. sdm670's defconfigs have no
   `CONFIG_DEBUG_INFO_BTF` (and no `PAHOLE`) - `git grep -n 'DEBUG_INFO_BTF|PAHOLE' a30605a54f3b --
   arch/arm64/configs/` -> nothing - so the fragment from task K6 must add `CONFIG_DEBUG_INFO_BTF=y`, and the
   build host needs pahole 1.13+.
