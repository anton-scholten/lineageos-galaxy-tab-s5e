# 2d6869d3a4ce: arm64: Add uprobe support
- Author / date: Pratyush Anand <panand@redhat.com>, 2017 (acked Catalin Marinas); no upstream SHA trailer
- Upstream: - (mainline "arm64: Add uprobe support", Pratyush Anand / Catalin Marinas, v4.19 era)

## Summary
Adds arm64 uprobes (new `arch/arm64/include/asm/uprobes.h` + `arch/arm64/kernel/probes/uprobes.c`, plus
`ARCH_SUPPORTS_UPROBES`). Only `arch/arm64/include/asm/thread_info.h` conflicts, and it is a **one-bit
collision**: upstream wants TIF bit 4 for `TIF_UPROBE`, Samsung already uses bit 4 for `TIF_FSCHECK`,
which sdm670 really uses. Resolution: keep both, move `TIF_UPROBE` to the free bit 5. Taking "theirs"
reproduces build error K4c in `analysis/build-test/port-first-errors.txt` verbatim.

## Conflicting files
- arch/arm64/include/asm/thread_info.h

## Why it conflicts
merge-tree on its own: **conflicts** (tree `184363ecb961ac68a961a41102ba86bc628cef2f`, exit 1).
Only `arch/arm64/include/asm/thread_info.h` conflicts; `arch/arm64/Kconfig`,
`arch/arm64/include/asm/{cacheflush.h,debug-monitors.h,ptrace.h}`, `arch/arm64/kernel/signal.c`,
`arch/arm64/mm/flush.c` and `arch/arm64/kernel/probes/Makefile` all auto-merged, and
`arch/arm64/include/asm/uprobes.h` + `arch/arm64/kernel/probes/uprobes.c` are new files (both present
in the merged tree `184363ecb9`, verified with `git cat-file -t`).

**Root cause: a direct collision on TIF bit 4.** Upstream used bit 4 for `TIF_UPROBE`; Samsung had
already used bit 4 in sdm670 for `TIF_FSCHECK` (their FS-is-USER_DS check). Three blocks, all the
same collision:

- Block 1, merged lines 83-87, after `#define TIF_FOREIGN_FPSTATE 3`:
  ours = `#define TIF_FSCHECK		4	/* Check FS is USER_DS on return */`
  (`a30605a54f3b:arch/arm64/include/asm/thread_info.h:83`);
  theirs = `#define TIF_UPROBE		4	/* uprobe breakpoint or singlestep */`.
- Block 2, merged lines 110-114, after `#define _TIF_SECCOMP`:
  ours = `#define _TIF_FSCHECK		(1 << TIF_FSCHECK)` (`a30605a54f3b:...:thread_info.h:106`);
  theirs = `#define _TIF_UPROBE		(1 << TIF_UPROBE)`.
- Block 3, merged lines 119-123, the third line of `_TIF_WORK_MASK`:
  ours = `				 _TIF_FSCHECK)` (`a30605a54f3b:...:thread_info.h:111`);
  theirs = `				 _TIF_UPROBE)`.

## Already in sdm670?
**no** for uprobe support; **yes** for `TIF_FSCHECK`, which must be kept.
- 1st searched line: `git grep -n 'TIF_FSCHECK' a30605a54f3b` -> 9 hits, including
  `a30605a54f3b:arch/arm64/include/asm/uaccess.h:77: set_thread_flag(TIF_FSCHECK);` and
  `a30605a54f3b:include/linux/syscalls.h:214-224` (`#ifdef TIF_FSCHECK` … `test_thread_flag(TIF_FSCHECK)`,
  `clear_thread_flag`). sdm670 users of the arm64 bit: `thread_info.h:83,106,111`, `uaccess.h:77`,
  `include/linux/syscalls.h:215,224`.
- 2nd searched line: `git grep -c 'TIF_FSCHECK' baa585f67e0e` (series head) -> **no hits** (exit 1), i.e.
  the Exynos tree genuinely lacks this flag, which is why upstream was free to use bit 4.
- `git cat-file -t a30605a54f3b:include/linux/uprobes.h` -> `blob` (the generic half exists; only the
  arm64 half is missing).
- `git show a30605a54f3b:arch/arm64/kernel/probes/Makefile` -> only the `CONFIG_KPROBES` line, no
  `CONFIG_UPROBES` line; `arch/arm64/kernel/Makefile` already has `obj-y += $(arm64-obj-y) vdso/ probes/`
  in both trees (`a30605a54f3b:arch/arm64/kernel/Makefile:64`), so `uprobes.o` will be picked up.
- `git grep -n 'UPROBES' a30605a54f3b -- arch/arm64/Kconfig` -> no hits (no `ARCH_SUPPORTS_UPROBES`).
- Free bits: sdm670 uses 0,1,2,3, then 4 (FSCHECK), then 7 (`TIF_NOHZ`), 8-11, 18-24.
  **Bits 5 and 6 are unused** (`a30605a54f3b:arch/arm64/include/asm/thread_info.h:79-95`), so there is
  room for `TIF_UPROBE` without renumbering anything.

### This conflict is already known to have broken a build
`analysis/build-test/port-first-errors.txt` line 3 is
`/tmp/claude-0/w/k670-port/arch/arm64/include/asm/uaccess.h:89:18: error: use of undeclared identifier 'TIF_FSCHECK'`
— i.e. the test build resolved this conflict by taking "theirs" (dropping `TIF_FSCHECK`) and then failed.
That is task K4c in `AGENT-TASKS.md`. Do not repeat it.

## Proposed resolution
MERGE — keep **both** flags, giving `TIF_UPROBE` a free bit instead of stealing bit 4.
In `arch/arm64/include/asm/thread_info.h`:

1. Block 1: keep `TIF_FSCHECK 4` **and** add
   `#define TIF_UPROBE		5	/* uprobe breakpoint or singlestep */`
   (bit 5; bit 6 is also free. Do not renumber `TIF_NOHZ`, `TIF_SINGLESTEP` or anything else — other
   vendor code may hardcode bit positions.)
2. Block 2: keep `_TIF_FSCHECK (1 << TIF_FSCHECK)` **and** add `_TIF_UPROBE (1 << TIF_UPROBE)`.
3. Block 3: keep `_TIF_FSCHECK)` **and** append `_TIF_UPROBE)`, i.e.
   `#define _TIF_WORK_MASK	(_TIF_NEED_RESCHED | _TIF_SIGPENDING | \`
   `				 _TIF_NOTIFY_RESUME | _TIF_FOREIGN_FPSTATE | \`
   `				 _TIF_FSCHECK | _TIF_UPROBE)`
   (`TIF_UPROBE` genuinely belongs in `_TIF_WORK_MASK` — that is what makes a uprobe trap wake up.)
4. Optional tidy: add a `*  TIF_UPROBE		- uprobe breakpoint or singlestep` line to the comment
   block at the top of the same file (`a30605a54f3b:arch/arm64/include/asm/thread_info.h:69-78`),
   which is missing for both flags.
5. Do not drop the already-merged `arch/arm64/Kconfig` `config ARCH_SUPPORTS_UPROBES / def_bool y`
   and the `obj-$(CONFIG_UPROBES) += uprobes.o decode-insn.o simulate-insn.o` line in
   `arch/arm64/kernel/probes/Makefile`; both are in the merged tree and are needed.

## Confidence
high: the merge-tree output was read directly, all three blocks are one-bit collisions with no
ambiguity, `TIF_FSCHECK`'s real users in sdm670 were enumerated by grep, the free bit numbers were read
off sdm670's own `TIF_*` list, and the resulting build failure is already documented in
`analysis/build-test/port-first-errors.txt` — so both the risk and the fix are evidenced, not guessed.

## Problems
Config gap for the lead: sdm670's tablet defconfig has uprobes/kprobes **off** —
`a30605a54f3b:arch/arm64/configs/gts4lvwifi_eur_open_defconfig:233: # CONFIG_KPROBES is not set` and
`:235: # CONFIG_UPROBES is not set`. Applying this commit alone therefore builds no uprobe code.
The defconfig list in `analysis/exyhyperbrick-trial/README.md` only mentions `CONFIG_KPROBES=y`;
`CONFIG_UPROBES=y` (which needs `CONFIG_ARCH_SUPPORTS_UPROBES`, added here) is required as well for
uprobes to exist. Android 16's `bpfloader` uses uprobes (UprobeStats loader), so this is on the
critical path, not optional.
