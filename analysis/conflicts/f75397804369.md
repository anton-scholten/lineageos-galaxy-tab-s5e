- Block 1, include/linux/mm.h ~line 324: ours (sdm670, a30605a54f3b:include/linux/mm.h:293-294) =
  `#define FAULT_FLAG_SPECULATIVE 0x200` + `#define FAULT_FLAG_PREFAULT_OLD 0x400` (android-4.9-q
  speculative page fault support); theirs (f75397804369) =
  `#define FAULT_FLAG_INTERRUPTIBLE 0x200` + a new `#define FAULT_FLAG_DEFAULT (FAULT_FLAG_ALLOW_RETRY |
  FAULT_FLAG_KILLABLE | FAULT_FLAG_INTERRUPTIBLE)`. **The two sides claim the same bit 0x200** -
  this is a value collision, not a textual overlap, so a naive "keep both" merge silently merges
  speculative-fault and interruptible-fault into one flag.
- Block 2, arch/arm64/mm/fault.c ~line 344: ours = `unsigned int mm_flags = FAULT_FLAG_ALLOW_RETRY |
  FAULT_FLAG_KILLABLE;` followed by a second line `struct vm_area_struct *vma = NULL;`;
  theirs = `unsigned int mm_flags = FAULT_FLAG_DEFAULT;` and no `vma` declaration. The `vma` local
  must stay: sdm670's do_page_fault() uses it for the speculative-fault path
  (a30605a54f3b:arch/arm64/mm/fault.c:345 declaration, :387 `handle_speculative_fault(mm, addr, mm_flags, &vma)`,
  :413-416 reuse).
## Already in sdm670?
partly. sdm670 already has FAULT_FLAG_SPECULATIVE 0x200 (a30605a54f3b:include/linux/mm.h:293) and
FAULT_FLAG_PREFAULT_OLD 0x400 (:294), i.e. the bit this commit wants is taken. It does **not** have the
new pieces: `git -C ~/work/k670 grep -n 'FAULT_FLAG_INTERRUPTIBLE' a30605a54f3b` -> nothing,
and `grep -n 'FAULT_FLAG_DEFAULT' a30605a54f3b -- include/linux/mm.h` -> nothing (only definition is
baa585f67e0e:include/linux/mm.h:320,323).
The behavioural half of the commit did land cleanly on its own: the fs/userfaultfd.c hunk
(`return_to_userland = fe->flags & FAULT_FLAG_INTERRUPTIBLE;` replacing the `FAULT_FLAG_USER|
FAULT_FLAG_KILLABLE` test) auto-merged in both the isolated run and the replay, because Mathias
Gluszczynski's adaptation already targets the 4.9 `struct fault_env` API
(f75397804369, fs/userfaultfd.c hunk).
## Proposed resolution
MERGE, with a mandatory renumber in include/linux/mm.h - do **not** take "theirs" verbatim:
(1) Keep sdm670's `FAULT_FLAG_SPECULATIVE 0x200` and `FAULT_FLAG_PREFAULT_OLD 0x400` unchanged.
(2) Define the new flag as `#define FAULT_FLAG_INTERRUPTIBLE 0x800` (the first free power of two;
sdm670's FAULT_FLAG_* set stops at 0x400, a30605a54f3b:include/linux/mm.h:283-294).
(3) Add the commit's `FAULT_FLAG_DEFAULT` as-is (the name is unused in sdm670).
(4) arch/arm64/mm/fault.c: keep `unsigned int mm_flags = FAULT_FLAG_DEFAULT;` from theirs **and** keep
sdm670's `struct vm_area_struct *vma = NULL;` line right after it.
Then check every other FAULT_FLAG_* definition added later in the series still uses a different bit:
at baa585f67e0e the only FAULT_FLAG_* values are 0x01-0x100 plus INTERRUPTIBLE 0x200, so 0x800 is free
across the whole series (`git grep -n -E '#define +FAULT_FLAG_[A-Z_0-9]+ +0x' baa585f67e0e`).
## Confidence
medium: the bit collision and the `vma` local are both proven from file:line in sdm670, and the merge is
textually trivial; the medium rating is because the fix silently changes a flag *value*, so if the
lead takes the "theirs" side by accident, sdm670's speculative page fault path
(mm/memory.c:2046,2992,3781,3832) starts behaving as if every fault were interruptible.
## Problems
Two things only the lead can settle, both outside this commit:
1. Because the fs/userfaultfd.c half of this commit auto-merges, the tree can end up with
   `return_to_userland = fe->flags & FAULT_FLAG_INTERRUPTIBLE;` while no architecture sets that flag.
   Every `handle_userfault()` caller on sdm670 (mm/memory.c:2997,3035 and mm/huge_memory.c:585,680) is
   reached only from do_page_fault(), so this commit's arm64 hunk is sufficient, but the lead should
   grep for any other place that builds a `fault_env` and calls handle_mm_fault/faultin_page.
2. The commit touches 27 architectures; only arch/arm64 exists on sdm670, so the other 26 hunks are
   dead weight in the patch and can be dropped when applying by hand.
