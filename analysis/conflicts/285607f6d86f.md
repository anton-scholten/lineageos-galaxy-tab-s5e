The series parent tree has the Exynos WAPI bit in the same enum slot that the
commit wants to use for WPA version 3, so both sides rewrote the same line.
- Block 1, include/uapi/linux/nl80211.h ~line 4126: ours (sdm670) has an enum with
  only `NL80211_WPA_VERSION_1 = 1 << 0`, `NL80211_WPA_VERSION_2 = 1 << 1`,

  renumbers it to `1 << 3`.
- Block 2, net/wireless/nl80211.c ~line 7939 (`nl80211_valid_wpa_versions()`):
  ours already allows `NL80211_WPA_VERSION_3` and nothing else; theirs allows
  `..._VERSION_3` plus `/*WAPI*/ NL80211_WAPI_VERSION_1`.

## Proposed resolution
DROP: sdm670 already carries the identical upstream change as `9b7ffd7b43e4`.
Keep sdm670's enum as-is (3 entries, no WAPI) and its `nl80211_valid_wpa_versions()`.

all. Nothing is lost by dropping; sdm670 ends up with the same WPA3 capability.
