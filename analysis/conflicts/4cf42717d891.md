## Why it conflicts
merge-tree on its own: conflicts (tree `0ad19a653697`, 2 files, 2 blocks).
- Block 1, include/linux/vmalloc.h ~line 22: ours has
  `#define VM_LOWMEM 0x00000100  /* Tracking of direct mapped lowmem */`, a
  Qualcomm/vendor flag on the exact bit the series wants; theirs replaces that
  line with `VM_FLUSH_RESET_PERMS 0x00000100`. This is a **semantic** conflict,
  not whitespace: taking "theirs" deletes VM_LOWMEM.
- Block 2, mm/vmalloc.c ~line 2067, in `vmalloc_exec()`: ours calls
  `__vmalloc_node(size, 1, GFP_KERNEL | __GFP_HIGHMEM, PAGE_KERNEL_EXEC, NUMA_NO_NODE, ...)`;
  theirs calls
  `__vmalloc_node_range(size, 1, VMALLOC_START, VMALLOC_END, GFP_KERNEL, PAGE_KERNEL_EXEC, VM_FLUSH_RESET_PERMS, NUMA_NO_NODE, ...)`.
The other ~100 lines of this commit auto-merge into mm/vmalloc.c: it adds
`vm_remove_mappings()`, `set_area_direct_map()`, rewrites `vm_unmap_aliases()`
into a static `_vm_unmap_aliases(start, end, flush)` plus a thin
`vm_unmap_aliases()` wrapper (EXPORT_SYMBOL_GPL kept), swaps
`remove_vm_area(addr)` for `vm_remove_mappings(area, deallocate_pages)` inside
`__vunmap()`, and adds `#include <linux/set_memory.h>`.

## Proposed resolution
MERGE (header side) / reject the mm/vmalloc.c rewrite. Concretely:
1. include/linux/vmalloc.h block 1: keep `VM_LOWMEM 0x00000100` **and** add
   `VM_FLUSH_RESET_PERMS 0x00000200`. Bit 0x200 is free in both trees (flags used
   at baa585f67e0e:include/linux/vmalloc.h are 0x1/0x2/0x4/0x8/0x20/0x40/0x80/0x100,
   and `/* bits [20..32] reserved */` starts at 0x100000). The equivalent
   alternative is to move `VM_LOWMEM` to 0x200 and give `VM_FLUSH_RESET_PERMS`
   upstream's 0x100; both VM_LOWMEM users use the macro by name, so either is a
   one-liner. Add-only is the smaller diff, so prefer it.
2. include/linux/vmalloc.h: keep the auto-merged `set_vm_flush_reset_perms()`
   helper in both the CONFIG_MMU and the `#else` branch (present at lines 143 and
   165 of the merged tree) — the BPF trampoline needs it.
3. mm/vmalloc.c: keep **ours** for block 2, and reject the whole auto-merged
   vm_remove_mappings/_vm_unmap_aliases/set_area_direct_map hunk (do not let it
   land). Reasons: it adds `#include <linux/set_memory.h>`, which does not exist in
   sdm670, and it calls `set_memory_nx`/`set_memory_rw`/`set_direct_map_invalid_noflush`/
   `set_direct_map_default_noflush`/`_vm_unmap_aliases`, none of which exist in
   sdm670's arm64 4.9. Losing the rewrite costs us nothing functionally on arm64:
   the whole feature is about resetting x86 direct-map permissions, and at
   baa585f67e0e the only caller of `vmalloc_exec()` is kernel/module.c:2792, so
   without the flag being passed, the exec page is freed exactly the way sdm670
   frees it today.
4. PREREQ if you decide to try the full apply instead: `2e71fb11d9a8`
   ("provide linux/set_memory.h", Michael Ellerman, series position 116, trial
   status CLEAN) adds include/linux/set_memory.h. Watch out: it is 9 commits
   *after* this one, and `1f9378f37a88` ("arm64: Select ARCH_HAS_SET_MEMORY",
   Angelo G. Del Regno, position 120, CLEAN) then makes that header include
   `<asm/set_memory.h>`, which **still does not exist in the series head's arm64**
   (`git ls-tree -r baa585f67e0e | grep set_memory.h` lists only
   arch/arm, arch/s390, arch/x86, asm-generic and linux versions). That chain is a
   cross-batch build risk — flag it, do not fix it here.
Why not DROP: this commit is effectively **required**, despite the `optional`
label. `kernel/bpf/trampoline.c:32` (`set_vm_flush_reset_perms(image);`) and
`kernel/bpf/bpf_struct_ops.c:601` (`set_vm_flush_reset_perms(st_map->image);`) at
baa585f67e0e call the helper, and both files come from trial-clean commits that
land much later: `5ab406ffb73f` "BACKPORT: bpf: Introduce BPF trampoline"
(position 1325, CLEAN) and `c49c98ee5ce7` "BACKPORT: bpf: Add struct_ops and TCP
congestion control" (position 2188, CLEAN). trampoline.o is built
unconditionally from kernel/bpf/Makefile:12 (`obj-$(CONFIG_BPF_JIT) += trampoline.o`)
with no #ifdef inside the file, so dropping this commit's header half breaks the
eBPF build with an undefined reference to `set_vm_flush_reset_perms`.
