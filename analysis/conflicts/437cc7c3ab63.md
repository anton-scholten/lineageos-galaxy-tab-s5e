## Proposed resolution
MERGE: take "theirs" for the single conflict block, i.e. drop sdm670's
`len = min(len, remainder);` line and use the series' `map_len` version.
This is not a judgement call — taking "ours" cannot work: the surrounding
already-merged context does `addr += map_len;` and passes `map_len`, so keeping
`len` there leaves `map_len` uninitialised and breaks the build.
The reasoning is arch-independent (remap_pfn_range() maps PAGE_ALIGN(size), so
advancing the user VA by the raw sg length can start the next sg entry inside an
already-mapped page), so it applies to the sdm670 ION code as-is. Optional
tweak: it fixes a latent mmap failure, not a boot or eBPF requirement.
