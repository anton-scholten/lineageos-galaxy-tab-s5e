## Proposed resolution
MERGE: take the commit, but **accept the deletion of the three Exynos files** - `git rm` / skip
`drivers/net/wireless/bcmdhd_101_16/dhd_linux_priv.h`, `drivers/rtc/rtc-s2mps17.c`, `drivers/rtc/rtc-s2mps18.c`.
Do **not** accept the merge-tree tree as-is: `merge-tree` leaves "Version 0c6f8a9a50ad of <file> left in tree", which
would *create* an Exynos Broadcom WiFi header and two Exynos RTC drivers inside a Qualcomm kernel. That is harmless
only by luck: `drivers/rtc/Makefile` @ `a30605a54f3b` lists every RTC driver explicitly and has no `s2mps` entry
(the Exynos one does, `drivers/rtc/Makefile:140-141` @ `0c6f8a9a50ad^`), so they would never compile - dead files.
Accepting the deletion loses nothing: the change to them was only the extra `wakeup_source_register()` argument, and
there is no Exynos WiFi or S2MP RTC on this SoC.

**Build break the lead must handle in the same pass** (this is the real cost of the commit). The prototype change
breaks callers that exist only in sdm670 and that **no commit in the 2599-commit series ever touches**
(`git log --oneline d54533f1546b..baa585f67e0e -- <file>` returns nothing for each). Enabled by the gts4lv defconfigs,
so they will fail to build:
- `drivers/char/diag/diagchar_core.c:4148` `wakeup_source_register("DIAG_WS")` -> `CONFIG_DIAG_CHAR=y`
  (`arch/arm64/configs/gts4lv_defconfig`); fix with the device created 6 lines above:
  `wakeup_source_register(driver->diag_dev, "DIAG_WS")`
- `drivers/tty/serial/msm_geni_serial.c:2793` `wakeup_source_register(dev_name(&pdev->dev))` ->
  `CONFIG_SERIAL_MSM_GENI=y`; fix: `wakeup_source_register(&pdev->dev, dev_name(&pdev->dev))`
- `net/ipc_router/ipc_router_core.c:1384` `wakeup_source_register(port_ptr->rx_ws_name)` ->
  `CONFIG_IPC_ROUTER=y`; no device in scope, use `NULL` (the new doc comment says "@dev: ... (or NULL if virtual)")
Three more callers are currently disabled (no `CONFIG_QPNP_SMB2`/`CONFIG_QPNP_SMB5`/`CONFIG_SMB1390_CHARGE_PUMP` in any
gts4lv defconfig) but would break if ever enabled: `drivers/power/supply/qcom/battery.c:1605`,
`drivers/power/supply/qcom/smb1390-charger.c:779`, `drivers/power/supply/qcom/step-chg-jeita.c:755`.
`drivers/staging/qca-wifi-host-cmn/qdf/linux/src/qdf_lock.c:273` already uses the 2-argument form but sits behind
`#if (LINUX_VERSION_CODE >= KERNEL_VERSION(4, 19, 110)) || defined(WAKEUP_SOURCE_DEV)`, so it is compiled out on 4.9 -
no change needed.

Alternative the lead may prefer (not my recommendation, but defensible): this commit is group `optional`, and nothing in
Android init reads `/sys/class/wakeup/`. Dropping it whole also drops the 3 call-site fixes, at the price of losing the
feature the S9 tree has. If the lead wants the feature, take MERGE + the 3 one-line call-site fixes above.
