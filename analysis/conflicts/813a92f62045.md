## Proposed resolution
MERGE, in kernel/sched/features.h only:
(1) keep ours verbatim - `SCHED_FEAT(FBT_STRICT_ORDER, false)` and the whole `EAS_USE_NEED_IDLE` block.
Both are referenced from sdm670's fair.c (fair.c:6171 and fair.c:7597), so dropping either is a build
break; and flipping `FBT_STRICT_ORDER` from false to true would silently change sdm670's
`find_best_target()` energy policy.
(2) add this commit's 3 lines at the end of the file: the one-line comment plus
`SCHED_FEAT(SUGOV_RT_MAX_FREQ, false)`. Default false is exactly the CAF/sdm670 behaviour the commit
wants to keep, so this is a safe addition.
(3) defensively keep theirs' 5-line `#ifdef CONFIG_SCHED_EMS ... SCHED_FEAT(EXYNOS_MS, ...) #endif`
block. It is dead on sdm670 (no CONFIG_SCHED_EMS, and sdm670's fair.c has no `sched_feat(EXYNOS_MS)`
call anywhere), but keeping it costs nothing and removes a landmine: `sched_feat(NAME)` is a compile
error if `SCHED_FEAT(NAME, ...)` is missing, and the Exy fair.c carries ten `sched_feat(EXYNOS_MS)`
calls (e.g. d54533f1546b:kernel/sched/fair.c:798,2656,5180). If any later series commit drags one of
those Exy hunks into sdm670's fair.c, a missing EXYNOS_MS becomes a build failure.
The kernel/sched/core.c half needs no action - it merges cleanly.
