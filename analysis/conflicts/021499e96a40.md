## Proposed resolution
MERGE for both blocks; PREREQ for the `FUSE_MAX_IN_ARGS` / `FUSE_MAX_OUT_ARGS` symbols.
- Prerequisite: `435bb390114e` BACKPORT: ANDROID: fuse-bpf: Add request UAPI must be merged first - it
  creates `include/uapi/linux/android_fuse.h` with `#define FUSE_MAX_IN_ARGS 5` and
  `#define FUSE_MAX_OUT_ARGS 3`, and the `#include <linux/android_fuse.h>` that this commit adds to
  fuse_i.h comes from here. That commit is itself a conflict (include/uapi/linux/Kbuild, batch K3-1),
  so it is not yet resolved. Also needed ahead of it: `f4cb49f3084c` BACKPORT: ANDROID: fuse: Move
  functions in preparation for fuse-bpf (batch K2a-4) and `462a37becb45` BACKPORT: ANDROID: fuse-bpf:
  Add request dispatcher (batch K3-2).
- Block 1, fs/fuse/dev.c: take **both** sides. Result:
  `if (!ret) { if (args->out.argvar) { BUG_ON(args->out.numargs == 0);
    ret = req->out.args[args->out.numargs - 1].size; }
    if (req->passthrough_filp != NULL) args->out.passthrough_filp = req->passthrough_filp; }`
  i.e. take the upstream "last out arg" size and keep Samsung's `passthrough_filp` copy-out. Dropping the
  latter breaks FUSE passthrough read/write on this tablet (fs/fuse/file.c reads
  `args.out.passthrough_filp`), so it is a functional regression, not a cosmetic one.
- Block 2, fs/fuse/fuse_i.h: keep **both** - `struct fuse_arg args[FUSE_MAX_OUT_ARGS];` **and**
  `struct file *passthrough_filp;`. Growing the array from 2 to 3 is safe for the existing users: every
  sdm670 user indexes `args[0]`/`args[1]` only (fs/fuse/dev.c:523-537, :579, :1956-1958,
  fs/fuse/dir.c:153-154, :294-295, :501-504, :619-620, :985-986, :1493-1494, :1656-1657,
  fs/fuse/cuse.c:310, :330, :448-454) and nothing takes `sizeof(args.out.args)`.
- The rest of the commit (fuse_get_req_force, `args->force` branch, `req->in.h.padding =
  args->error_in`, the out-args copy-back, `args[3]` -> `args[FUSE_MAX_IN_ARGS]`) merged cleanly or is
  outside the conflict - take it as-is. Note the copy-back `memcpy(args->out.args, req->out.args, ...)`
  is placed before the passthrough_filp copy in the resolved version, so the two do not overwrite
  each other (they touch different fields).
