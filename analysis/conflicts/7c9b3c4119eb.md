## Proposed resolution
MERGE:  — apply as-is; there is no conflict to resolve. What it does to
`__purge_vmap_area_lazy()` (all line numbers at `a30605a54f3b`, pre-image):
- replaces `bool do_free = false;` with `int resched_threshold;`, and replaces
  `if (!do_free) return false;` with an early `if (unlikely(valist == NULL)) return false;`
  plus a `/* TODO: to calculate a flush range without looping. */` comment;
- adds `resched_threshold = (int) lazy_max_pages() << 1;` after `flush_tlb_kernel_range(start, end);`
- gates the existing preempt point:
  `cond_resched_lock(&vmap_area_lock);` → 
  `if (atomic_read(&vmap_lazy_nr) < resched_threshold) cond_resched_lock(&vmap_area_lock);`

The `cond_resched_lock()` it wraps is already in sdm670 (from `68b90437585c`), so the patch composes with the
existing code rather than replacing it. `lazy_max_pages()`, `atomic_read()` and `atomic_t vmap_lazy_nr` all
exist in sdm670's `mm/vmalloc.c`, so no prerequisite is missing.

Behavioural note for the lead (this is the point of the patch): before it, every freed vmap area causes a
scheduling point; after it, a scheduling point only happens once the lazy-free backlog has dropped below
`2 * lazy_max_pages()`. That trades latency-under-memory-pressure for throughput. It is a genuine
optional-but-desirable power/latency tuning, in the `optional` group, and it is self-contained (one function,
no API change), so the risk of taking it is low.

Ordering note: the *next* commit, `0a115d7aaf34` "mm/vmalloc.c: convert vmap_lazy_nr to atomic_long_t"
(series position 109), converts `atomic_read(&vmap_lazy_nr)` → `atomic_long_read(&vmap_lazy_nr)` and
`atomic_sub` → `atomic_long_sub` in this same function. It applied CLEAN in the trial, but when I check it in
isolation with `git merge-tree --write-tree --merge-base=0a115d7aaf34^ a30605a54f3b 0a115d7aaf34` it
**does** conflict (tree `b0d77661d71b337eed380631ed37387d38b9fde2`, 3 conflict blocks, all inside
`__purge_vmap_area_lazy`, around the `do_free` / `resched_threshold` lines). **No K2 brief exists for it**,
because the trial classified it CLEAN and it is therefore not in any batch. The lead should open one:
the resolution is mechanical — drop the now-obsolete `bool do_free = false;`, keep
`resched_threshold = lazy_max_pages() << 1;`, and take theirs for the `atomic_long_*` hunk.
