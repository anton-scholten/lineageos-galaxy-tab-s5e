## Proposed resolution
MERGE for the three file.c blocks; PREREQ for the fuse-bpf scaffolding.
- Prerequisite chain (all already identified in 021499e96a40 and 04db905cb97f):
  `435bb390114e` ANDROID: fuse-bpf: Add request UAPI (batch K3-1, conflict) ->
  `90d81d6b357b` ANDROID: fuse-bpf: Add lookup backing helpers (CLEAN; creates fs/fuse/backing.c) ->
  `462a37becb45` ANDROID: fuse-bpf: Add request dispatcher (batch K3-2, conflict). That last one is also
  what adds `config FUSE_BPF` to fs/fuse/Kconfig (fs/fuse/Kconfig:20 @ baa585f67e0e) - sdm670's
  fs/fuse/Kconfig has **no** `FUSE_BPF` at all (0 hits), so until `462a37becb45` is merged every
  `#ifdef CONFIG_FUSE_BPF` in this commit is an undefined symbol and the build breaks.
  Without `backing.c` the fs/fuse/backing.c modify/delete cannot be resolved as "modify".
- Block 1: take theirs verbatim - it is all new code behind `#ifdef CONFIG_FUSE_BPF`, and ours has
  nothing at that point. Keep the `#ifdef`/`#endif`.
- Blocks 2 and 3: take **both** sides. Result for each of `fuse_file_mmap()` and `fuse_direct_mmap()`:
  `struct fuse_file *ff = file->private_data;` then `ff->passthrough_enabled = 0;` then
  `#ifdef CONFIG_FUSE_BPF` / `if (fuse_file_has_backing(file)) return -ENODEV;` / `#endif`, then the
  rest of the function unchanged. Taking "theirs" wholesale here would delete
  `ff->passthrough_enabled = 0;` and silently re-enable the Samsung passthrough path for mmap'd files -
  it compiles, and it breaks FUSE passthrough mmap silently.
  Conversely do not reorder so that the `return -ENODEV` runs before `passthrough_enabled = 0`; either
  order is functionally acceptable here because `-ENODEV` aborts the mmap anyway, but keeping the
  Samsung line first keeps the diff minimal.
- Blocks 4 and 5: take theirs verbatim (empty "ours" side, pure additions).
- Note the commit is a **behavioural gate**: with `CONFIG_FUSE_BPF` unset (the default in the sdm670
  defconfig, which has no `CONFIG_FUSE_BPF` line at all) every added hunk compiles out and sdm670 keeps
  its existing FUSE behaviour, which is exactly what the commit message promises.
